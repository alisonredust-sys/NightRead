## 1. 产品定位

### 1.1 一句话

作者把自己的作品放进来，AI 扮演一批**有身份的读者**，从短评、长评、同人三个层次给出反馈；作者可以回复、可以点赞，系统记住这些偏好，让下一批反馈更像"真的有人在读"。

### 1.2 它解决什么

| 真实痛点 | 对应机制 |
| --- | --- |
| 没人看，得不到反馈 | 短评区进入即有 10 条，翻页即续 |
| 反馈太水，只有"好看" | 长评区给不设上限的专业赏析 |
| 想知道读者会怎么二创 | 同人区生成 1500–3000 字的衍生 |
| 读者的意见互相打架，不知道听谁 | 设定 > 正文 > 作者回复 > 点赞 的四级优先级 |
| 不同作品之间人设会崩 | 系列级事实卡 + 分层记忆 |

### 1.3 它不解决什么

- **不替代真实读者。** 所有内容由 AI 模拟。界面不暴露生成行为，是为了保住"评论区"的沉浸感，作者本人始终知情。
- **不保证评价客观。** 立场由虚拟读者人设决定，作者可以换角度重生成。
- **不做内容审核。** 单机自用，生成内容直接呈现。

### 1.4 五条设计原则

1. **设定是唯一权威源。** 任何生成都从事实卡出发，事实卡错了就是作者错了，系统不二次猜测。
2. **首屏即内容，其余显式触发。** 每个评论场首次进入自动生成第一批；之后每一页都由作者点击触发，已生成的内容永不重复生成。
3. **批次即页。** 分页单位是"一次生成"，不是"一条内容"。
4. **三区一条管线。** 短评、长评、同人共用同一套「拼上下文 → 调用 → 校验 → 落库」，只是参数不同。
5. **同人是单向门。** 系列的内容可以流进同人，同人的产出不流回系列。

## 2. 核心概念与命名

| 概念 | 定义 | 备注 |
| --- | --- | --- |
| 系列 Series | 一本书的全部内容容器 | 一个系列 = 一本书；含正文、设定集、系列评论、同人 |
| 正文作品 Work | 系列下的一篇文本 | 正传 / 外传 / 番外并列，各自有短评、长评 |
| 设定集 Codex | 系列级的作者手记 | 作者自己写的设定，不分类；最高优先级，AI 只读不改 |
| 批次 Batch | 一次生成产出的全部条目 | 一批 = 一页 |
| 支流 Stream | 带关键词的独立批次序列 | 界面上伪装成"搜索结果" |
| 虚拟读者 Persona | 带昵称、头像、口吻、立场的模拟读者 | 系列内复用，形成"常驻读者" |
| 风格卡 StyleCard | 从被点赞同人里抽出的文风描述 | 可编辑、可禁用、带权重 |
| 场景 Scene | 一次生成调用的类型 | `work_short` / `work_long` / `series_short` / `series_long` / `doujin` / `doujin_short` / `reply` |

### 2.1 信息架构

```
主界面（门面）
├── 系列
│   ├── 正文
│   │   └── 作品（正传 / 外传 / 番外）
│   │       ├── 短评
│   │       └── 长评
│   ├── 设定集
│   ├── 系列评论
│   │   ├── 短评
│   │   └── 长评
│   └── 同人
│       └── 同人详情
│           └── 短评
└── 设置
```

### 2.2 导航模型

- **主界面（第 0 层）**：全屏轮换背景 + 两个入口——「系列」「设置」。没有底部 tab，没有侧滑抽屉。
- **系列页（第 1 层）**：当前这一本书。顶部有系列切换器（下拉列出全部系列 + 「新建系列」），正文放四张入口卡。切换系列不退回主界面。
- **四区（第 2 层）**：正文 / 设定集 / 系列评论 / 同人。
- **区内页（第 3 层）**：阅读页、同人详情、设定集编辑等。
- 返回：区内页 → 四区 → 系列页 → 主界面。主界面按返回键退出 App（二次确认）。

> 为什么没有"系列列表页"：一个系列就是一本书，作者的书通常个位数，列表页会让每次进书多点一层。切换器既是列表也是入口。

## 3. 生成管线（三区共用）

### 3.1 管线五步

```
buildContext(scene, scope, keyword)
  → call(model, messages, jsonSchema)
  → parse + validate（条数 / 长度 / 重复 / 禁用词）
  → persistBatch(status=complete|partial)
  → streamToUI（逐条落草稿，完成后原子提交）
```

### 3.2 场景参数表

| 场景 | 每页条数 | 单条长度 | 人设 | 上下文范围 | 输出 JSON 根 |
| --- | --- | --- | --- | --- | --- |
| `work_short` | 10 | ≤100 字 | 普通读者口吻 | 当前作品 + 事实卡 | `comments[]` |
| `work_long` | 2 | 不限（建议 1200–3000） | 专业读者口吻 | 当前作品 + 章节摘要 + 事实卡 | `items[]` |
| `series_short` | 10 | ≤100 字 | 读者口吻，允许跨篇比较 | 全系列摘要 + 事实卡 | `comments[]` |
| `series_long` | 2 | 不限（建议 1200–3000） | 专业读者口吻 | 全系列摘要 + 事实卡 + 跨篇对照 | `items[]` |
| `doujin` | 1 | 1500–3000 字 | 资深读者 / 同人作者 | 系列摘要 + 事实卡 + 风格卡 | `items[]` |
| `doujin_short` | 10 | ≤100 字 | 读者口吻，评这篇同人 | 该同人正文 + 同人标题 | `comments[]` |
| `reply` | 1–2 | 20–100 字 | 该评论者 + 至多 1 名路人 | 被回复的评论 + 作品摘要 + 作者回复 | `replies[]` |

### 3.3 四级优先级：不是口号，是拼装顺序

| 级别 | 内容 | 放在哪 | 冲突时 | 进缓存前缀 |
| --- | --- | --- | --- | --- |
| P0 | 系统规则（角色、格式、禁止项） | system message | 最高 | 是 |
| P1 | 设定集事实卡 | user 前缀第 1 块 | 覆盖一切事实 | 是 |
| P2 | 正文（全文或检索片段） | user 前缀第 2 块 | 覆盖作者回复 | 是 |
| P3 | 作者回复（只有标了"设定补充"的才升到 P1；其余进"作者态度摘要"） | user 中段 | 低于正文 | 否 |
| P4 | 点赞风格卡 | user 尾部 | 最低，只影响表达 | 否 |

**硬约束写法**（P1 块开头固定句）：

> 以下是本作品的既有事实，**不得违背、不得改写、不得让角色做出与身份或生死状态矛盾的行为**。若与后续材料冲突，一律以此为准。

**两条机制细节**：

1. **缓存前缀必须稳定。** P1 + P2 的顺序与内容在同一作品内保持不变，让模型商的自动上下文缓存命中；P3/P4 放到后面，因为它们经常变。
2. **P3 不能反推 P2。** 作者回复说"其实他早就知道"，但正文没写，那正文优先；回复只能补充正文**未涉及**的部分。

### 3.4 生成参数

| 参数 | 值 | 理由 |
| --- | --- | --- |
| temperature | 短评 1.0、长评 0.8、同人 0.9、回复 0.9 | 短评要散，长评要稳 |
| max_tokens | 短评 1200、长评 8000（触顶则分段续写）、同人 6000、回复 400 | 长评不设字数上限，必须留续写通道 |
| 输出格式 | JSON（严格 schema） | 免解析失败 |
| 超时 | 90s | 同人长文可能慢 |
| 重试 | 1 次，仅对网络错误 | 校验失败不自动重试，避免重复扣费 |

## 4. 分页、首屏与"搜索"

### 4.1 分页模型

- **页码 = 已生成批次。** 生成 3 批就有 3 页。
- **首次进入自动生成第一批。** 每个评论场（作品短评、作品长评、系列短评、系列长评、同人、同人短评）在该 scope 下从未有过批次时，进入即生成第 1 批。只自动一次，之后进入直接展示已有内容。
- **向前翻 = 读本地。** 翻回第 2 页不发起任何请求。
- **向后翻到边界 = 生成。** 已经是最后一页时，点「下一页」触发第 N+1 批。
- **页脚**：只显示「第 2 页」，右侧「下一页」。**不显示总页数、不显示"已生成"**——否则会暴露这是按需生成而不是全量数据。
- **空批次不占页。** 生成失败或返回 0 条，回滚页码。

### 4.2 "搜索"：外观是检索，行为是再生成一批

这是产品的核心伪装，规则必须写死：

| 层 | 表现 | 实际 |
| --- | --- | --- |
| 搜索框 | 放大镜图标，placeholder「搜索关键词」 | 输入并提交即触发一次以该词为角度的生成 |
| 预设词 | 显示为「热门搜索」标签 | 点击即触发该角度的生成 |
| 加载态 | 转圈 + 「搜索中…」 | 实际在调模型，可能 5–30 秒 |
| 结果 | 10 条"搜索结果" | 就是一批新评论 |
| 清空 | 清空关键词，回到原列表 | 退出支流，主序列位置不变 |
| 历史 | 搜索框聚焦时下拉「搜索历史」 | 已生成过的关键词批次，可直接回访，不重复生成 |

- **严禁出现的文案**：「生成」「AI」「正在为你创作」「本批」「已生成 N 页」。
- **允许出现的文案**：「搜索中」「暂无相关结果」「换个关键词试试」。
- 支流内部仍是独立页码序列，只是对外表现为"搜索结果第 1 页"。
- 同一关键词再次搜索 → 直接展示已存的结果，**不重新生成**。

### 4.3 预设关键词（短评、长评各一套，显示为"热门搜索"）

| 区 | 预设词 |
| --- | --- |
| 短评 | 角色形象、角色设定、外貌、剧情节奏、描写手法、角色关系、读者情感 |
| 长评 | 主题立意、叙事结构、人物弧光、语言风格、伏笔与回收、类型成规、情感说服力 |

**同人区不设预设词**：同人是创作，选题应当来自作者自己输入的角度，给一堆"感情线 / 黑化 / if 线"反而会把创作挤进模板。同人页只保留搜索框。

可在设置里增删改短评、长评两套。

## 5. 作者回复与互动

### 5.1 入口

- 长按任意评论 / 同人正文 → 底部弹出菜单：`回复`、`复制`、`隐藏这条`（仅本地）。
- 同人正文的"回复"= 在同人详情下短评流末尾插入一条作者回复。

### 5.2 互动规则

| 项 | 规则 |
| --- | --- |
| 触发 | 作者发出回复后，自动生成 1 条（被回复者），50% 概率再生成 1 条（路人） |
| 递归 | 不自动递归。作者再回才再生成 |
| 深度 | 回复树最深 5 层，超出只允许平铺 |
| 语气 | 被回复者沿用其 persona 口吻与立场，不因被怼就改口 |
| 路人 | 从系列 persona 池里挑，不重复出现同一个人 |
| 时间 | 回复时间 = 当前时间；AI 回复 = 当前时间 + 1–40 分钟随机 |

### 5.3 「设定补充」开关

- 回复输入框上方有一个开关：`这条回复要写进设定`（默认关）。
- 打开 → 回复内容进入 P1 事实卡（标记来源 = 作者回复）。
- 关闭 → 只进 P3「作者态度摘要」，摘要只影响后续评论的语气倾向，不影响事实。

### 5.4 数据形态

评论与回复是**树**（`reply.parent_id`），展示为两层缩进；第 3 层起折叠为「查看 N 条回复」。

## 6. 点赞与风格卡

### 6.1 点赞

- 只对同人正文可点赞（不点赞评论、不点赞长评）。
- 点赞数 = 作者自己的赞（1）+ AI 模拟的路人赞（0–N，生成时随机但落库后不变）。
- 取消点赞 → 风格卡权重回退，可撤销。

### 6.2 风格卡生成

点赞后异步触发一次抽取（不阻塞 UI）：

| 字段 | 说明 |
| --- | --- |
| `name` | 如「冷峻短句」「第二人称浸入」 |
| `syntax` | 句长、标点密度、段落长度 |
| `viewpoint` | 人称、视角切换习惯 |
| `imagery` | 高频意象、感官偏好 |
| `rhythm` | 场景切换速度、留白习惯 |
| `avoid` | 该文风**不**做的事（如"不写心理独白"） |
| `weight` | = 点赞同人篇数，可手动加减 |
| `enabled` | 可禁用，禁用后不参与生成但不删除 |

### 6.3 使用规则

- 生成同人时，注入权重最高的 **2 张**启用中的风格卡。
- 风格卡只影响"怎么写"，**不影响"写什么"**：情节仍由设定 + 正文 + 本次搜索关键词决定。
- 风格卡可编辑：作者觉得描述不准，直接改文字，改完保存即可。
- 风格卡是系列级的，跨同人累积。

## 7. 记忆与一致性

### 7.1 五层记忆

| 层 | 内容 | 生成方式 | 生命周期 |
| --- | --- | --- | --- |
| L0 事实卡 | 角色、事件、世界规则 | 手写 + AI 抽候选 + 人工确认 | 永久，作者可改 |
| L1 章节摘要 | 每章 150–300 字 | 导入后自动生成，正文变更时失效 | 跟随正文 |
| L2 当前作品全文 | 作品原文 | 导入 | 永久 |
| L3 检索片段 | 按关键词从全文切出的 800 字块 | 运行时 | 不落库 |
| L4 已生成评论摘要 | 上一批的核心论点，用于避免重复 | 每批完成后生成 | 保留最近 3 批 |

### 7.2 上下文预算

| 块 | 上限 | 超出时 |
| --- | --- | --- |
| 系统规则 | 800 token | 固定 |
| 事实卡 | 4000 token | 按重要性截断：主要角色 > 近期事件 > 世界规则 |
| 正文 / 摘要 | 12000 token | 单篇 ≤ 8000 字直出全文；超过则用 L1 摘要 + L3 检索 |
| 作者补充 | 1500 token | 只取最近 20 条 |
| 风格卡 | 800 token | 只取 2 张 |
| 输出预留 | 2000–6000 token | — |

单次请求输入硬上限 **24k token**，超了先砍 L3，再砍 L1，最后截断 L0 的次要条目。

### 7.3 一致性策略

- **硬事实**（姓名、身份、生死、时间线、已发生事件）：由 L0 锁死，生成前注入，生成后**不做**全文校验。
- **软解读**（性格、动机、CP 感）：允许不同读者有分歧，甚至允许同一读者在不同批次里改口（人设立场固定，但表达可以变）。
- **同一批内不重复**：L4 记录上一批的开头 30 字与核心论点，prompt 里要求"不要重复以下观点"。

### 7.4 设定集：作者手写，不做 AI 抽取

- 设定集是**作者自己的创作**，不是从正文里"提炼"出来的东西。AI 没有资格替作者决定世界观。
- 因此没有「从正文抽取」这个功能，也没有角色 / 事件 / 世界规则的分类——**平铺的手记列表**即可，顺序由作者决定。
- 每条只有三样东西：标题、正文、修改时间。
- 这些手记原样进入 P1 上下文块，是整条优先级里最高的一层；AI 只能服从，不能改写。
- 副产品：省掉了抽取的 token 成本，也省掉了"AI 抽错了还得逐条确认"的交互。

### 8.1 主界面（门面）

```
┌─────────────────────────────┐
│                             │
│      （全屏轮换背景）         │
│        半透明遮罩             │
│                             │
│         书  架  名            │
│                             │
│      ┌───────────────┐      │
│      │    系  列      │      │
│      └───────────────┘      │
│      ┌───────────────┐      │
│      │    设  置      │      │
│      └───────────────┘      │
│                             │
│                    [换一张] │
└─────────────────────────────┘
```

| 区 | 内容 |
| --- | --- |
| 背景 | 全屏图，每次进入随机换一张（不与上次相同），带半透明遮罩保证文字可读 |
| 标题 | 应用名 / 最近在读的系列名 |
| 入口 | 两个大按钮：系列、设置 |
| 换一张 | 右下角图标按钮，点一下换下一张（不写入"下次随机"的排除规则） |
| 返回 | 退出 App，二次确认 |

**只有两个入口，不设底部 tab、不设抽屉。** 背景轮换是这一页的主要视觉，入口越少越好看。

### 8.2 系列页

```
┌─────────────────────────────┐
│ ‹ 返回    《长夜将尽》 ▾    ⋯ │
├─────────────────────────────┤
│  [封面] 长夜将尽              │
│        12.4 万字 · 3 篇       │
│        连载中                 │
├─────────────────────────────┤
│ ┌─────────────────────────┐ │
│ │ 正文          3 篇 · 继续阅读 │ │
│ ├─────────────────────────┤ │
│ │ 设定集        18 条事实      │ │
│ ├─────────────────────────┤ │
│ │ 系列评论      短评 3 · 长评 1 │ │
│ ├─────────────────────────┤ │
│ │ 同人          5 篇 · ♡ 12    │ │
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

- 顶部系列切换器：点书名弹出全部系列 + 「新建系列」+ 「管理系列」。
- **首次使用（一个系列都没有）**：点「系列」直接进新建流程，不走空列表。
- `⋯`：编辑系列信息 / 重新生成摘要 / 删除系列。
- 四张卡按此顺序固定：正文、设定集、系列评论、同人。

### 8.3 正文区 · 作品列表

- 分组：正传 / 外传 / 番外（由导入时的分类决定，分类可自定义）。
- 每篇：标题、字数、阅读进度条、短评数、长评数。
- 底部：「导入新作品」。
- 点进 → 阅读页。

### 8.4 阅读页（三 tab）

```
正文 | 短评 | 长评
──────────────────────────────
（当前 tab 内容）
```

| 短评 | 见 8.5 |
| 长评 | 见 8.6 |

### 8.5 短评区（单篇 / 系列 同构）

```
┌─────────────────────────────┐
│ 🔍 搜索关键词                 │
│  热门搜索：角色形象 外貌 剧情节奏… │
├─────────────────────────────┤
│ ● 昵称        3 天前         │
│   评论正文（≤100 字）        │
│   ♡ 12   💬 2               │
├─────────────────────────────┤
│ …（共 10 条）                │
├─────────────────────────────┤
│  上一页      第 2 页      下一页 → │
└─────────────────────────────┘
```

- **首次进入**：直接显示骨架屏 +「搜索中…」式的加载（对外不区分是"加载"还是"生成"），完成后呈现 10 条。这是自动生成的第 1 批。
- **再次进入**：直接展示已有批次，无加载。
- **搜索态**：输入关键词提交 → 转为「搜索结果」视图，顶部保留搜索框中的词，出现小「清除」按钮；清空回到原列表且位置不变。
- **翻页**：点「下一页」若已是最后一页，短暂加载后出现第 N+1 页；**按钮文案不变、页码不跳变、不显示总页数**。
- **长按评论**：回复 / 复制 / 隐藏。
- **失败**：保留已到达条目，底部一行灰字「加载失败，点击重试」，不出现"生成失败"字样。

### 8.6 长评区

- 每页 2 条，卡片式。
- 卡片：虚拟读者（头像 + 昵称 + 一句身份标签，如「写了十年书评」）、标题、五星评分、正文摘要（前 120 字）、「展开全文」。
- 展开后全文不设上限（软建议 1200–3000 字），段落间距加大，可复制；超过一屏时显示阅读进度。
- 其余（搜索 / 热门搜索 / 分页 / 长按）与短评区一致。

### 8.7 设定集（作者手记）

```
┌─────────────────────────────┐
│ ‹返回   设定集          新建 │
├─────────────────────────────┤
│ 你写的设定。AI 只读，不改。   │
│ ┌─────────────────────────┐ │
│ │ 01  守夜人的边界   3 天前 │ │
│ │ 守夜人不能救人，只能拖延。 │ │
│ └─────────────────────────┘ │
│ ┌─────────────────────────┐ │
│ │ 02  灯             3 天前 │ │
│ │ 点灯的意思是「有人在等」。 │ │
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

- **不分组、不分类**，就是一则一则往下写，顺序即思路。
- 每则：序号、标题、正文、修改时间。没有"来源"徽标，因为全部是作者写的。
- 右上角「新建」写一则；长按某则 → 编辑 / 删除 / 置顶。
- 没有"从正文抽取"，没有 AI 生成的候选，没有"待确认"状态。
- 页面同样支持轮换背景（见 8.13）。

### 8.8 系列评论

- 两个 tab：短评 / 长评。
- 短评同 8.5，长评同 8.6，scope = 系列。
- 与单篇评论的区别写进 prompt：必须谈"整本 + 外传 + 设定"的整体感，允许跨篇比较，禁止逐章复述。

### 8.9 同人区（系列级）

- 每页 1 篇，整页卡片：标题、正文预览（前 300 字）、风格标签、点赞数、评论数。
- 底部：`♡ 点赞`、`写评论`、`下一页`。
- 只有搜索框，**没有预设词**（见 4.3）；分页规则同上。
- 点进 → 同人详情。

### 8.10 同人详情

- 正文（1500–3000 字），顶部标题 + 风格标签。
- 操作条：点赞 / 复制 / 隐藏。
- 下方短评流（10 条/页，可搜索），规则同 8.5。
- 作者可长按评论回复。

### 8.12 世界的真实

```
┌─ API ────────────────────────┐
│ Base URL   https://api.deepseek.com │
│ API Key    sk-••••••••  [测试连接] │
│ 模型       deepseek-chat            │
├─ 余额 ───────────────────────┤
│ ¥ 42.18          刷新于 20:41 │
│ 赠金 ¥0.00 · 充值 ¥42.18      │
├─ 今日 ───────────────────────┤
│ 12,340 tokens · 约 ¥0.42      │
│ 生成 6 次 · 日预算 ¥5.00 ▓░░░ │
├─ 账本 ───────────────────────┤
│ 20:31 同人     6.1k   ¥0.08   │
│ 20:12 短评     9.8k   ¥0.03   │
└──────────────────────────────┘
```

**关键行为**：

- 进入页面自动刷新一次余额；下拉可再刷。
- **余额来自接口，今日消耗来自本地账本**，两者口径不同；差额 > 10% 时显示一行灰字：「可能有其他设备或网页版在使用同一 key」。
- 日预算到达 80% 弹一次提醒，100% 再弹一次；**不阻断生成**（软上限），可在设置里改为硬上限。
- Key 用 Android Keystore 加密存储，UI 只显示后 4 位。
- 「测试连接」调 `GET /user/balance`，成功显示余额，失败给具体 HTTP 状态。
- 这一页可以出现"生成""AI"字样——它是设置页，不是评论区。

> 已查证：DeepSeek 只有 `GET /user/balance`（返回 `is_available`、`balance_infos[]` 的 currency / total_balance / granted_balance / topped_up_balance），**没有**用量或今日消耗接口。今日消耗只能由客户端逐次记账。

### 8.13 背景系统

**作用范围**：主界面、设置页、设定集页。其余页面（阅读页、评论区、同人详情）保持纯色，避免干扰阅读。

| 项 | 规格 |
| --- | --- |
| 预置图 | 24 张，4 类各 6 张：雾山、旧城、星图、纸纹 |
| 格式 | WebP，单张 ≤ 120KB，边长 1080×1920 适配主流屏 |
| 打包 | 随 APK 内置，约 3MB；完全离线可用 |

| 轮换 | 每次进入该页面随机换一张，排除上次那张；点「换一张」手动切 |

## 10. AI 调用契约

### 10.1 请求骨架

```json
{
  "model": "deepseek-chat",
  "temperature": 1.0,
  "max_tokens": 2000,
  "response_format": { "type": "json_object" },
  "messages": [
    { "role": "system", "content": "<P0 系统规则>" },
    { "role": "user", "content": "<P1 设定集>\n\n<P2 正文或摘要>\n\n<P3 作者补充>\n\n<P4 风格卡>\n\n<任务指令>" }
  ]
}
```

### 10.2 系统规则（P0）要点

- 你是一名读者，不是助手；不要解释自己在做什么。
- 严格遵守 P1 的事实，不得让角色做出与身份/生死矛盾的行为。
- 输出必须是 JSON，字段名固定。
- 评论里不要出现"作为 AI""根据设定"这类元叙述。
- 不要重复 P5 列出的已有观点。

### 10.3 输出 schema

**短评**

```json
{ "comments": [ { "persona": "P07", "text": "…" } ] }
```

**长评**

```json
{ "items": [ { "persona": "P03", "title": "…", "score": 4,
               "body": "…", "sections": ["结构", "人物", "语言"] } ] }
```

**同人**

```json
{ "items": [ { "title": "…", "body": "…",
               "style_refs": ["SC1"], "crossover": false } ] }
```

**回复**

```json
{ "replies": [ { "persona": "P07", "text": "…", "is_author_target": true } ] }
```

### 10.4 校验规则

| 检查 | 不通过时 |
| --- | --- |
| JSON 可解析 | 整批失败，提示重试 |
| 条数 == 期望 | 少于期望则接受并标记 partial |
| 短评 ≤100 字 | 超长丢弃，不截断（截断会毁掉结尾）；不足 10 条按 partial 处理 |
| 长评无上限 | 仅受 max_tokens 约束，触顶后续写 |
| persona 在池内 | 重新分配一个 |
| 与上一批前 30 字重复 | 丢弃该条 |
| 含禁用词（"作为AI""生成"） | 丢弃该条 |

## 11. 成本模型与账本

### 11.1 单页成本估算

按 DeepSeek 量级（输入 ¥2/百万 token、输出 ¥3/百万 token，用户可在设置里改价）：

| 场景 | 输入 | 输出 | 单价/页 | 备注 |
| --- | --- | --- | --- | --- |
| 短评 ×10 | 8k–20k | 1.2k | ¥0.02–0.05 | 命中缓存可降到 1/5 |
| 长评 ×2 | 10k–25k | 4k | ¥0.03–0.07 | 单条 1500 字时更高 |
| 同人 ×1 | 12k–30k | 6k | ¥0.05–0.12 | 最贵 |
| 回复 ×1–2 | 3k–6k | 0.3k | ¥0.01 | — |

### 11.2 省钱四招

1. **稳定前缀吃缓存**：P1 + P2 顺序不变，缓存命中后输入成本约 1/10。
2. **首屏只自动一批**：每个评论场只在第一次进入时自动生成，且失败不自动重试。
3. **支流复用**：同一关键词只生成一次，回头看不重新生成。
4. **翻旧页零成本**：向前翻页只读本地。

### 11.3 账本

- 每次请求成功/失败都写 `UsageLog`，字段来自响应 `usage`。
- 今日消耗 = 当天日志按 `cost` 求和；日切按本地时区 0 点。
- 批次的 `cost` 同时冗余在 `Batch` 上，便于按场景统计。

## 12. 状态机

### 12.1 批次

```
idle ──触发──> generating ──成功──> complete
                    │
                    ├──部分到达──> partial ──继续──> generating
                    └──失败──────> failed ──重试──> generating
```

`partial` 的批次计入页数，但页脚不显示"未完成"（会暴露生成），只允许"继续加载"。

### 12.2 页面

```
empty ──首次进入（自动生成第 1 批）──> generating ──> browsing(1)
browsing(n) ──下一页──> n < max ? browsing(n+1) : generating ──> browsing(n+1)
```

自动生成只在 `count(Batch where scope && scene) == 0` 时发生。同一 scope 同一时刻只允许一个生成任务，并发点击直接复用结果。

### 12.3 搜索

```
off ──提交关键词──> searching ──有历史──> result(page=1)
                            └──无历史──> generating ──> result(page=1)
result ──清除关键词──> off（主列表位置保留）
```

### 12.4 全局

无 key → 所有评论区显示「暂无内容」空态 + 一个不显眼的「去设置」；不报错、不暴露生成。

## 13. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 启动 | 冷启动 < 1.5s；主界面背景图预解码，避免白闪 |
| 长文渲染 | 10 万字作品按章节分页，单章懒加载；滚动不掉帧 |
| 列表 | 每页 10 条，`LazyColumn` 复用；头像本地生成，不走网络 |
| 背景 | 图库预压缩；切换用 300ms 交叉淡入；不参与滚动重绘 |
| 离线 | 已生成内容全可读；评论区显示已有批次，翻页提示「网络不可用」 |
| 隐私 | 作品与 key 只存本机；除模型商外无第三方请求；卸载即清空 |
| 主题 | 亮/暗跟随系统；背景只作用于指定三页，正文卡片强制不透明 |
| 无障碍 | 字号可放大到 150%；对比度 ≥ 4.5:1 |
| 错误 | 所有错误有中文可读文案 + 重试入口，不暴露原始堆栈 |

## 14. 边界与异常

| 场景 | 处理 |
| --- | --- |
| 上传 20 万字整本 | 提示「建议按章导入，否则生成质量与费用都会变差」，允许继续 |
| 上传空文档 / 解析失败 | 明确报错，保留原文件供重试 |
| 首次进入但无 key | 空态「暂无内容」，不自动调用、不报错 |
| 首次自动生成失败 | 标记 failed，**不自动重试**（避免重复扣费）；下次进入再试一次，仍失败则等作者手动触发 |
| 同一批重复点击 | 加锁，二次点击无效，复用同一任务 |
| 生成中退出页面 | 后台继续，完成后通知；回来直接看到 |
| 生成中杀进程 | 批次标 failed，下次进入静默重试一次 |
| 模型返回条数不足 | 接受 partial，不提示"未完成"，只允许继续加载 |
| 评论重复语义 | L4 去重 + 校验层丢弃开头重复的条目 |
| 角色同名 | 设定集冲突提示，不自动合并 |
| 系列只有一篇正文 | 系列评论仍可用，prompt 要求"从整体结构谈"，避免与单篇重复 |
| 删除系列 | 二次确认，级联删除作品、批次、同人；账本保留（那是钱） |
| 余额查询失败 | 显示上次缓存值 + 时间戳 + 错误类型 |
| key 失效 | 评论区空态 + 「去设置」；设置页给明确错误 |
| 背景图过大 | 导入时压缩到 ≤ 200KB，超限提示 |
| 预置图缺失 | 回退到纯色渐变，不崩 |
