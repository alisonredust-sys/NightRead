# 测试方案 · v0.5

## 0. 这一版修的三个 bug（先看根因）

你报的三个问题，其实是同一个 bug 的三种表现。

| 现象 | 根因 |
| --- | --- |
| 填系列名时看不见文本框 | 深色主题下输入框底色与弹层底色几乎相同（#14130f vs #1d1b16），边框也接近，整块看起来是纯色 |
| 创建后返回按钮无效 | 返回本身没坏；是前后页面渲染抛错，画面卡住，看起来像"点了没反应" |
| 正文/设定集点不开 | **导航时没把系列 ID 传过去**，目标页拿到 `undefined` 直接抛错 |

第三条是主因。`go('works')` 只传了页面名，没传 `sid`，`vWorks` 里 `seriesById(undefined)` 返回空，再取 `.works` 就崩了。返回按钮"无效"也是因为它前面的操作已经把页面搞崩了。

修法：
1. 所有 `data-act="go"` 都带上当前 `sid`
2. 输入框改 `surface-2` 底 + 1.5px 边框 + 显式 `-webkit-text-fill-color`，深色下也看得清
3. 加 `color-scheme: light dark`，避免 WebView 强制反色把表单搞花

## 7. 已知风险

1. **键盘遮挡**：目前靠 `adjustResize` + 弹层贴底，理论上没问题，但部分机型（含 vivo）输入法会盖住弹层下半部分。M5 就是测这个，不过的话我改成「输入时弹层上移」。
2. **WebView 版本**：老机型 WebView 可能不支持 `color-mix()`，抽屉背景会变透明。M3 能看出来。
3. **localStorage 容量**：WebView 一般 5MB，两万字正文 + 若干图片够用；但如果用户导入整本几十万字，会超。这一版没做溢出提示。
